# Go to Rust PDF parity

This ledger is the cutover contract. `Implemented` means a public Rust API and focused verification exist; it does not imply OXPDF consumer, CI, release, or fuzz proof.

## Cutover proof still required

- The executable map freezes all 678 exact Go names without a one-to-one Rust-port claim: 25 adapter corpus names are a named differential-vector inventory; the remaining 653 are explicit inventory-only categories (adapter 518, CLI 101, WASM 4, core 12, pdfapi 16, root 2). The oracle currently covers all 22 committed PDF fixtures, five text edits, form and annotation mutations; four semantic/error differences are explicit.
- CLI/WASM compatibility is not yet cutover proof. Rust parses the shared legacy CLI paths and has a runtime smoke for `inspect`, `query`, `edit`, `validate`, and `profile`; its native replacements are `overlay stamp` for `overlay text`, `ocr apply` for both Go OCR paths, and `signature prepare`/`apply` for `signature re-sign`. Rust CLI implements `xfa datasets` and `xfa dataset-set`; the read-only mapping and exact removal remain core APIs without Rust CLI commands. These are not compatibility shims, and flags/JSON/exit schemas are not yet frozen against Go. Rust retains the three Go WASM call signatures and adds `binasExtractPDFText`, but its JSON/result shapes are Rust contracts rather than frozen Go JSON parity.
- The Rust OXPDF facade now consumes `binas-pdf` directly through a local path dependency and has focused engine contracts. That proves local development wiring only; a published/installed dependency and the complete engine-facing suite remain cutover gates.
- A nightly/manual Linux AddressSanitizer `graph_readers` 60-second fuzz smoke is configured, not hosted-proven. Run broader fuzz duration and performance comparison; obtain hosted proof for the Windows/Linux/macOS CI matrix, release packaging, migration, and rollback proof.
- Keep Go as rollback until the cutover window closes.
