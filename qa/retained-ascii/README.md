# Retained ASCII local fixture and independent oracle

Original Apache-2.0 fixture generator and bounded QA oracle. Run with the existing bundled Python, not the default Miniconda Python:

```powershell
$pdfOraclePython = 'C:\Users\garae\.cache\codex-runtimes\codex-primary-runtime\dependencies\python\python.exe'
& $pdfOraclePython -B qa/retained-ascii/oracle.py generate
& $pdfOraclePython -B qa/retained-ascii/oracle.py verify SOURCE.pdf OUTPUT.pdf Incremental REPORT.json
& $pdfOraclePython -B qa/retained-ascii/oracle.py verify SOURCE.pdf OUTPUT.pdf Compact REPORT.json
& $pdfOraclePython -B qa/retained-ascii/oracle.py self-test SOURCE.pdf OUTPUT.pdf Compact MUTANT_EVIDENCE_DIRECTORY
```

Generation defaults to `crates/binas-pdf/tests/fixtures/retained-ascii`. The manifest records provenance and SHA-256 for each generated fixture. Generation is deterministic, including the encryption control's explicit ID bytes. No tool is downloaded or installed.

The admitted fixtures are `retained-ascii-plain.pdf` and `retained-ascii-flate.pdf`. They contain 27 retained objects: IDs 1 through 26, plus unreferenced sentinel stream 28, all generation zero; `/Size` is 29. Page zero (object 3) uses target stream 4. Its first `ALPHA` text-show operation is replaced with `OMEGA`; `KEEP` and every other operand/operator must remain exact. Objects include valid fonted untouched pages, independent media/crop boxes and rotation, an RGB image, metadata, Info, outlines, destination and embedded-file name trees, attachment bytes, an AcroForm text widget and appearance, and the unreachable sentinel. Only the target stream's bytes and `/Length` may change. No broad dictionary filtering is used.

The source must equal one of the generator's exact admitted fixture byte strings. pypdf 6.10.0 independently parses in strict mode, inventories every active xref object identity and generation (including the unreachable sentinel), compares typed dictionaries, encoded/decoded stream hashes, resolved geometry, exact raw ContentStream operations, trailer values including IDs/Info/Root/Size, mode-specific `/Prev`, revision count, and original byte prefix for Incremental. The source and Compact candidate must be warning-free. Incremental candidate intake permits exactly one pinned diagnostic, `Xref table not zero-indexed. ID numbers for objects will be corrected.`, only after an independently emitted legitimate nonzero-subsection control reproduces it and verifies every resulting object ID/offset and exact replacement ContentStream. The installed parser emits this diagnostic for any first classic-xref subsection whose ID is nonzero under `strict=True`; no non-strict downgrade is used. All messages are retained and phase-labeled; any other warning, later warning, or Python warning fails the check. Incremental parsing is explicitly **qualified diagnostic-bearing strict parsing**, not warning-free or conformance evidence. Object-body hashes are recorded as evidence; dictionary serialization whitespace and ordering may change, so body hashes are not a preservation invariant. Stream payload hashes are invariants except for the target.

The independent Poppler `pdfinfo -box -f 1 -l 3` parser must exit zero with no stderr and agree on all three page counts/sizes/rotation/boxes. Its exact command, version, stdout, stderr, and extracted geometry lines are retained for each source/output pair. Python executable/version and pypdf/Pillow versions are also recorded. Running with `-O` is rejected so required control assertions cannot disappear.

Poppler 26.07.0 renders only PDF pages 2 and 3 with pinned options at 96 DPI; PNG dimensions and decoded pixel hashes must match. The target intentionally has no selected font, matching the narrow P2b admitted raw-text case. Target appearance is explicitly **NotChecked**; no valid target-glyph or broad PDF rendering compatibility claim follows from these fixtures.

The installed renderer emits `Syntax Error: No display font for 'Symbol'` and `Syntax Error: No display font for 'ArialUnicode'` on independently valid Helvetica and Courier fonted controls. A truly empty blank control emits no diagnostics. This supports the inference that the messages arise during lazy ambient font initialization. Baseline qualification requires the exact empty diagnostic string for the blank control and the exact pinned two messages for both fonted controls; each before/after fonted render must match those same messages exactly. Any additional diagnostic, nonzero exit, missing renderer, or changed baseline fails closed. Full commands, source/control hashes, stderr, versions, and image hashes remain in durable evidence. No stderr is hidden or blanket ignored. The result is explicitly a **diagnostic-bearing renderer comparison**, not warning-free or conformance evidence. This limitation is separate from the phase-qualified pypdf parsing checks.

Self-tests persist actual mutated PDFs and their comparison reports. A negative counts as detected only if its intended named preservation check fails without an oracle exception. Cases cover wrong target, collateral target text, crop geometry, metadata, attachment, page loss, font resources, image pixels, trailer IDs, unreferenced sentinel change, and Compact sentinel omission. A separate image negative exercises only the renderer pixel comparator.

Prepare-time refusal fixtures are `fonted-refusal.pdf`, `shared-owner.pdf`, `repeated-owner.pdf`, `foreign-owner.pdf`, `indirect-length.pdf`, `unsupported-gs.pdf`, and `signature-marker.pdf`. The signature fixture is only a syntactic security marker, **not a genuine signed PDF**. `encrypted-fonted.pdf` is an actual RC4-40 encrypted valid-font PDF generated with installed pypdf; it characterizes the encrypted security-preflight boundary and does not establish encrypted text editing. RC4-40 is used only for a local refusal control.

This gate covers these exact local fixtures and this retained ASCII edit. It is not a universal compatibility, standards conformance, target appearance, or arbitrary PDF preservation certificate.
